# Предварительный аудит RedAge 3.0

Дата осмотра: 2026-11-07. Исходник взят из `ragemp-pro/redage_v3`, commit `23730b8cd464f86c47eaae6f80d182cd651092b2` от 2026-03-06. Пользователь сообщил, что получил разрешение владельца; это сообщение не является самостоятельной проверкой прав. Сохраняй письменное разрешение владельца.

## Что уже видно по структуре

- Серверная часть: C# / RAGE:MP, проект `NeptuneEvo`, целевая платформа `netcoreapp3.1`.
- Игровые подсистемы включают аккаунты, персонажей, бизнесы, фракции, дома, инвентарь, работы, транспорт, телефон, организации, задания, казино и мир.
- Клиентская логика: JavaScript (`src_client`); интерфейс: Svelte (`src_cef`).
- Три SQL-файла: `main.sql`, `mainconfig.sql`, `mainlogs.sql`; суммарно около 22,457 строк и 145 `CREATE TABLE` объявлений.
- В `conf.json` оставлены upstream defaults — имя unofficial server, freeroam, 100 слотов, порт 22005. Это не готовая конфигурация для публичного запуска.

## Риски и ограничения для следующих шагов

1. **Секреты БД:** в upstream `settings/mainDB.json` были заполненные реквизиты подключения; также в `Main.cs` была закомментирована строка со статическими реквизитами website DB. В локальной копии оба источника очищены, а `settings/mainDB.json` игнорируется `.gitignore`. Если реквизиты могли быть действующими, владелец должен сменить их и проверить логи БД. Не вставляй настоящие значения в Git, README, логи или этот чат.
2. **Устаревшая платформа:** .NET Core 3.1 и перечисленные NuGet-зависимости старые. Перед интернет-запуском нужно проверить совместимость с текущим RAGE:MP runtime и план безопасного обновления; «просто обновить всё» может сломать API и сборку.
3. **Сборка пока не проверена:** в окружении нет `dotnet`; серверные бинарники/runtime и собранный `client_packages` в этот срез не включены. Я не запускал неизвестные бинарники.
4. **Частичный срез:** включены C#-, JS- и Svelte-исходники, SQL, JSON и настройки. Исключены большие RAGE:MP бинарники/runtime, собранные клиентские пакеты и тяжёлые картинки/шрифты/видео. Поэтому сейчас это материал для аудита и разработки, а не запускаемый архив.
5. **Права на составные части:** в исходном GitHub-репозитории не найден LICENSE-файл. Сохрани письменное разрешение владельца и уточни, покрывает ли оно модификации, ассеты, внешние библиотеки и публикацию/хостинг производной сборки.
6. **Хостинг:** для игрового сервера потребуется проверить поддержку RAGE:MP, постоянного процесса и необходимых сетевых портов. Replit не следует считать подходящим production-хостингом до проверки этих ограничений.

## Предлагаемый порядок работ

1. Получить подтверждение границ разрешения и полный перечень переданных файлов/ассетов.
2. Сделать резервную копию и подготовить чистую конфигурацию без секретов; отдельно хранить dev/test и production settings.
3. Разобрать стартовую цепочку, сборку .NET, CEF/клиентские сборки и импорт SQL на тестовой БД.
4. Провести статический аудит: доступ к БД, админские команды, сетевые события/валидация, авторизация, платежи/донаты и обработка пользовательских данных.
5. Составить приоритетный план исправлений и только затем менять игровые системы.
6. Проверить базовую сборку и запуск в изолированной среде; production-развёртывание — после устранения критичных проблем и настройки резервного копирования/мониторинга.
