# Отложенные идеи после завершения аудита

## Solo-mode: живой город и симуляция фракций NPC

**Статус: отложено по прямому указанию владельца до завершения полного аудита, исправлений и прогонов.** Не входит в текущий scope; production code не меняется для этой функции.

### Цель владельца

Для одиночной игры оживить город NPC и со временем симулировать часть игровых систем: фракции и их конфликты, работу/ресурсы, торговлю, крафт, захват зон и реакции NPC на игрока. Боты не должны быть способом накрутки публичного онлайна.

### Технические ограничения и предварительная оценка

- Локальная ambient population GTA (прохожие/трафик) — клиентская визуальная симуляция; она не создаёт общих server-authoritative участников фракций и может различаться у разных игроков.
- Синхронизированный server-created ped — world entity, но сам по себе **не** `ExtPlayer`: у него нет автоматически аккаунта, session, CharacterData, player inventory и прав на обработчики, рассчитанные на настоящих игроков.
- Поэтому «создать запись аккаунта и вызвать те же player functions» не является безопасной готовой архитектурой. Нужны отдельные `NpcAgent`/`NpcPersona` модели и общие domain services, принимающие явный тип actor; нельзя подделывать `ExtPlayer`, обходить validation или выдавать NPC за реальный онлайн.
- Конкретные API (`NAPI.Ped`/JS API), pathfinding/vehicle AI, streaming, sync ownership и ограничения RAGE:MP надо подтвердить по точной версии runtime и существующему NeptuneEvo SDK. Утверждение про `mp.peds.new()` и цифра «15–30 активных ботов» не подтверждены для этого snapshot; capacity нужно измерять на staging.
- Большая часть фракционных/экономических систем сейчас привязана к реальному `ExtPlayer`. Сначала надо завершить аудит и выделить чистые server-side services для операций; иначе NPC-интеграция будет копировать правила и создавать обходы.

### Возможный порядок после аудита

1. Решить: только личный solo-mode или серверная общая симуляция; определить видимость NPC, их права и политику публичного отображения онлайна.
2. Сделать feature-flagged ambient NPC prototype без аккаунтов и без влияния на экономику.
3. Выделить `NpcAgent` + bounded scheduler/state machine; для дальних зон применять низкочастотную/offline simulation, а визуальные peds создавать только близко к игроку.
4. Добавлять по одной системе: простые маршруты/работники → ограниченные ресурсы и crafting → faction patrols → тестовый territory event.
5. Для каждого шага — бюджеты сущностей/tick/CPU/RAM, deterministic tests, restart/recovery, player-vs-NPC permissions, no fake online counters.

Эта запись — только backlog/архитектурная заметка. Ни NPC, ни fake accounts, ни fake online не реализованы.
