## 2. Важные системные модули, часто забываемые в MVP

1. **Feature flags / kill switches** — выключить комментарии, реакции или отдельную механику без релиза.
2. **Audit log** — административные и модераторские действия с неизменяемой историей.
3. **Abuse prevention** — rate limits, ограничения повторных действий, spam controls, блокировка аккаунта.
4. **Email delivery** — подтверждение email, восстановление доступа, критические уведомления; мониторинг bounce/failure.
5. **Observability** — структурированные логи, error tracking, health endpoint, базовые метрики приложения без персональных данных.
6. **Backups & restore drills** — автоматические резервные копии и документированная проверка восстановления.
7. **Data lifecycle** — сроки хранения, удаление/анонимизация, политика медиа, обработка запросов субъекта данных.
8. **Content safety workflow** — жалобы, скрытие, апелляция/повторная проверка, причины решений.
9. **Moderation operations** — SLA очереди, приоритеты, эскалации, нагрузка на модератора.
10. **Challenge lifecycle** — draft → scheduled → open → paused → completed → archived; защита от гонок на дедлайне.
11. **Idempotency** — публикация, реакции, join, XP, уведомления не должны дублироваться при повторах запроса.
12. **Accessibility** — проверяемая клавиатурная навигация, контраст, labels, reduced motion.
13. **SEO / share metadata** — только для публичных страниц заданий и лендинга, без раскрытия приватных данных.
14. **Localization readiness** — строки интерфейса не хардкодить в компонентах; стартовый язык русский.
15. **Operational admin** — возможность исправить ошибочно созданное задание, скрыть контент и отозвать доступ без SQL вручную.

## 3. P0 / P1 / P2

### P0 — прототип и закрытый пилот
Auth, минимальный onboarding, профили, каталог и детали заданий, участие, редактор публикации, media pipeline, лента задания, реакции, ограниченные комментарии (configurable), XP ledger, базовые достижения, inbox статусов, жалобы, ручная модерация, admin CMS, базовые privacy settings, analytics events, audit log, rate limiting, email verification/recovery, error tracking, backups.

### P1 — после проверки базового цикла
Сохранение/избранное, расширенный поиск, приглашения и referral attribution (без финансовой награды), командные задания, сезоны, тематические подборки, расширенные уведомления, модераторские инструменты массовых действий, аналитический дашборд, эксперименты с onboarding, локализация второго языка.

### P2 — только при доказанном спросе
AI-помощник по рецепту, распознавание блюда/ингредиентов, meal planning, pantry, shopping list, интеграции с ритейлом, marketplace, creator monetization, live cook-alongs, нативные приложения, сложные социальные механики.

## 4. Технологические компоненты и библиотеки

Не подключать библиотеку только потому, что она популярна. Перед установкой проверять лицензию, активность, совместимость, безопасность, размер bundle и реальную потребность.

| Задача | Кандидат | Статус |
|---|---|---|
| Framework | Next.js App Router | Рекомендован |
| UI | React + Tailwind CSS | Рекомендован |
| UI primitives | Официальный shadcn/ui + Radix primitives | Рекомендован, точечно |
| Icons | lucide-react | Рекомендован |
| Forms | React Hook Form + Zod | Рекомендован для сложных форм |
| Database | PostgreSQL | Рекомендована |
| ORM/migrations | Drizzle ORM + Drizzle Kit | Рекомендован |
| Auth | Better Auth | Кандидат; проверить recovery/email/session и соответствие требованиям |
| Email | Российский/доступный SMTP или транзакционный провайдер | Не выбран; сравнить до реализации |
| Object storage | S3-compatible provider в РФ | Не выбран |
| Image processing | Sharp | Кандидат для resize/metadata stripping |
| Rate limiting | PostgreSQL-backed MVP; Redis только при необходимости | Не усложнять заранее |
| Validation | Zod | Рекомендован |
| Unit/component tests | Vitest + Testing Library | Рекомендованы |
| E2E | Playwright | Рекомендован |

| Storybook | Storybook | Опционально, после появления повторяемой дизайн-системы |
| Visual regression | Playwright screenshots / Chromatic | Позже |
| CI | GitHub Actions | Рекомендован |
| Dependency updates | Dependabot | Рекомендован |
| Security scanning | CodeQL + dependency alerts | После появления кода |

| Package manager | pnpm | Рекомендован |
| API contracts | Zod schemas; OpenAPI только при реальной потребности внешнего API | Не добавлять заранее |

### Критерии выбора внешних сервисов
- хранение персональных данных и резервных копий в РФ, где это требуется законом;
- договор обработки данных и список субподрядчиков;
- доступность из РФ и способы оплаты;
- стоимость хранения, запросов, egress и резервирования;
- экспорт данных и отсутствие vendor lock-in;
- SLA, мониторинг, incident process;
- возможность миграции без переписывания доменного слоя.

## 5. Что не добавлять в первый релиз
Redis, Kafka, RabbitMQ, BullMQ, Kubernetes, микросервисы, GraphQL, WebSockets, OpenSearch, AI API, payment gateway, рекламную сеть, публичные DM, сложный recommendation engine. Возвращаться только при измеренной потребности.

## 6. Definition of Ready / Done
- У каждой функции есть пользовательская проблема, владелец и метрика.
- У каждой записи P0 есть happy path, negative path, permission checks и состояния загрузки/ошибки.
- Критические действия идемпотентны.
- Любые привилегированные действия проверяются на сервере.
- Для пользовательского контента определены правила хранения, удаления, модерации и жалоб.
- Тесты покрывают права доступа, начисление XP, статусы публикации и дедлайны.
- В production не уходят секреты, персональные данные в логи и тестовые учётные данные.
- Никакая внешняя интеграция не считается выбранной без отдельного сравнения.
